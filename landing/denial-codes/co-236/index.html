CO-236: Procedure/modifier combination not compatible with another same-day service

Group CO — Contractual Obligation · Denial Code Library · Updated October 29, 2026

What CO-236 means

This procedure or procedure/modifier combination is not compatible with another procedure or procedure/modifier combination provided on the same day, per the payer's clinical edit logic (typically NCCI-based). The pairing itself is the problem.

What it usually means on a real remittance

CO-236 denies the conflicting line. It differs from CO-97 in focus: rather than 'already included in what we paid,' it says 'these two things cannot be billed together this way' — usually a mutually exclusive pair or an edit that a modifier failed to satisfy.

Common causes

  • Two procedures billed the same day are mutually exclusive or comprehensive/component pairs under NCCI, billed with a modifier the edit doesn't allow
  • A modifier was used to bypass an edit on a combination the documentation doesn't support as distinct
  • Add-on or bundled-designated codes combined in a way the payer's edits prohibit
  • The combination is legitimate but requires a specific modifier (e.g. 59/X) that was missing or misplaced

How to fix or appeal CO-236

  1. Identify the conflicting pair and look up the NCCI edit and its modifier indicator for the date of service
  2. Review the documentation for distinctness: different site, session, or encounter
  3. If distinct, submit a corrected claim with the proper separating modifier and documentation ready
  4. If not distinct, bill the single comprehensive code and write off the component per the adjustment
  5. Feed the pair back into your scrubber rules so the same combination is caught pre-submission
Corrected claim or appeal? Corrected claim — with a separating modifier if the services were genuinely distinct, or as the comprehensive code if they weren't.

CO-236 — frequently asked questions

How is CO-236 different from CO-97?

CO-97 means one service was denied as included in another that was paid. CO-236 flags the combination itself as incompatible — the pairing (or pairing-plus-modifier) fails the edit before payment logic even runs. Both come from the same NCCI family of edits.

What fixes a CO-236?

Documentation that the services were distinct: separate sites, separate sessions, or separate encounters — plus the correct separating modifier on a corrected claim. If they weren't distinct, the correct action is billing the comprehensive code.

How do I prevent CO-236?

Pre-submission NCCI edit checks including modifier indicators, so incompatible pairs are resolved by coding before the claim leaves. This is a standard scrubber function — ClaimPaid runs procedure-pair edits on every claim.
